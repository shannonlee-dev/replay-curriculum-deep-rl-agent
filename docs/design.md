# 설계

## 접근 방식

완승만 보상하는 긴 게임에서는 성공 신호가 드뭅니다. 완승 가능한 후반 상태에서 시작해 남은 카드 수를 늘리되, 이전 난이도도 함께 학습해 망각을 줄이는 접근을 사용합니다. 게임 규칙과 보상은 모든 단계에서 동일합니다.

| 선택 | 의도와 트레이드오프 |
| --- | --- |
| Win-only reward | 완승에 학습을 집중하지만 성공 신호가 드묾 |
| Reverse 상태 생성 | 성공 경험을 제공하지만 무작위 게임과 분포가 다름 |
| 과거 난이도 혼합 | 이전 능력을 연습하는 대신 현재 난이도의 학습 비중이 줄어듦 |
| 고정 seed 평가 | 단계 간 비교가 쉽지만 반복 선택에 쓰여 최종 일반화 평가로 부적합 |
| 고정 balanced panel | 모델 간 비교 기준을 유지하지만 후반 난이도 평가 비용이 발생 |

## 환경 계약

- 카드 2~99, 오름차순 pile 2개·내림차순 pile 2개, 손패 최대 8장.
- ±10 backward trick과 `END_TURN`을 지원. 덱이 남으면 턴당 최소 2장, 비면 최소 1장.
- 관측 300차원: 손패·덱·이미 낸 카드의 포함 여부 각 98개, pile top 4개, 현재 턴 낸 장수, 덱 크기.
- 행동 393개: `(card - 2) * 4 + pile`, `END_TURN=392`. 마스크로 합법 행동을 제한.
- 보상은 완승 1, 패배·중간 행동 0. 남은 카드·낸 카드·턴 길이는 진단에만 사용.

덱에 포함된 카드는 관측되지만 **정확한 순서와 teacher 계획은 노출되지 않습니다.** 기존 모델과 호환되도록 관측 인코딩과 행동 번호를 유지합니다.

## Reverse 상태 생성

98장을 네 pile에 배정하고 pile별 합법 수순에 일부 ±10 트릭을 삽입합니다. pile 내부 순서를 보존해 수순을 섞고, 그 계획으로 덱을 구성합니다. 실제 합법 행동을 두 장씩 수행해 지정한 남은 카드 수의 턴 경계까지 진행합니다.

생성 상태는 원래 게임에서 도달 가능하며 최소 하나의 완승 수순을 갖습니다. 다만 덱과 시작 상태의 분포가 무작위 전체 게임인 `natural`과 다르므로 reverse 승률만으로 실제 게임 성능을 판단할 수 없습니다.

## Replay와 모델 선택

Replay는 **에피소드 시작 상태의 혼합**입니다. PPO 경험 버퍼를 재사용하는 방식이 아닙니다. 각 환경이 독립 RNG로 현재·최근 난이도와 R12/R20 anchor를 선택합니다.

진급은 현재·직전·과거 난이도의 승률과 최소 학습량으로 결정합니다. 예산이 소진되면 정체로 기록합니다. 모델 선택은 현재 난이도 승률(`best_current_stage`) 또는 고정 평가 panel의 평균·최저 승률(`best_balanced`)을 사용합니다. 기본값과 전환 규칙은 [실행 가이드](usage.md)에 정리했습니다.

## 호환성과 복원의 범위

모델을 불러오면 policy/value 가중치, optimizer 상태, global timestep을 복원하고 PPO 학습 설정은 config를 적용합니다. `net_arch`는 새 모델에만 적용됩니다.

단계 전환은 환경을 교체하므로 미완료 에피소드가 종료됩니다. 재시작 시 curriculum 진행 상태·환경 RNG·진행 중 에피소드·best 비교 기록·단계 예산은 복원하지 않습니다. 따라서 `--resume`은 정확한 학습 궤적 재현을 의미하지 않습니다.

## 최적화의 한계

PPO의 `gamma=0.999`는 완승 보상을 할인하므로 성공까지의 길이도 학습에 영향을 줍니다. Entropy 항도 탐색 목적에 포함됩니다. Win-only reward를 사용하지만 비할인 완승 확률만을 정확히 최적화한다고 볼 수는 없습니다.
